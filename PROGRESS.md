### Этап 3 — просмотр исходника и выделение
- Клик по карточке открывает исходник в центре: SVG вставляется инлайн (`fetch` → `innerHTML`), вписан в
  область с отступом 24px (`src/components/SourceViewer.tsx`). Активная карточка подсвечена.
- `src/lib/svgGroups.ts` — индекс групп после монтирования, исходник только читается:
  - служебные обёртки пропускаются: пока в контейнере ровно одна `<g>` (не считая прозрачного фона и
    `defs`/`clipPath`), сцена начинается внутри неё;
  - рамка группы = объединение `getBBox()` фигур через `getCTM()` (в единицах viewBox), обрезанное
    `clip-path` самой группы и предков и границей холста — `getBBox()` группы обрезку не учитывает
    (без этого окно в s16 и лес в s15 давали рамки за пределами картинки).
- Рамки наведения (синий пунктир) и выделения (розовая) рисуются отдельным `<svg>` поверх с тем же viewBox,
  `pointer-events: none`.
- Состояние в `src/store/editor.ts`: открытый исходник, индекс групп, hover, выделение. Наведение —
  ближайшая `<g>` вверх от `event.target`; клик — выделить; Shift+клик — добавить (повторный Shift+клик
  внутри выделенного — убрать); ↑/↓ и кнопки — уровень выше/ниже (вниз — обратно к исходно кликнутой
  группе); Esc — снять; клик мимо — снять. Кнопка «← Назад к исходникам».
- Справа секция «Выделение»: id (у гоферов id нет → «группа №N»), размер в единицах viewBox, число
  вложенных элементов и групп, уровень.
- Проверено headless Chrome (puppeteer-core во временной папке, не в проекте) на s11, s15, s16:
  отдельно выделяются гофер, предмет и декор; рамки без `clip-path` совпадают с раскладкой браузера
  (расхождение 0,0px); Shift+клик → 2 рамки, Esc → 0; `innerHTML` исходника до и после
  взаимодействия идентичен; «Назад» возвращает пустую область; ошибок в консоли нет.

- «↑ Уровень выше / ↓ Уровень ниже» — в панели над рабочей областью рядом с «← Назад»; панель

  контур 2px с заливкой 12%, наведение — пунктир 1px; толщина не зависит от масштаба и браузера.
- Проверено Playwright в Chromium и WebKit (движок Safari) при 1280 и 1024px и после уменьшения окна:
  пересечений кнопок/заголовков/карточек нет, ничего не выходит за свою зону, отступ ровно 24px,
  толщина рамок 2px/1px. Настоящий Safari не запускался.

### Попытка заменить набор (17.10.2026) — отклонена, остаёмся на гоферах
Запрос: заменить гоферов на «взрослый» плоский корпоративный стиль. Итог: **набор не меняется**, решение
принято по заранее оговорённому правилу «если автогруппировка не даёт чистого результата за сессию —
откат к гоферам без дальнейших поисков».
- Проверены (свободные лицензии): Illlustrations / Vijay Verma (MIT/CC0), Lukasz Adam (CC0/MIT), Flowbite,
  GLPI, GitLab, Momentum, Wix, Humaaans. DrawKit и unDraw исключены по лицензии (запрет публичного распространения).
- Урок: число `<g>` в файле ничего не доказывает. У Illlustrations 90–170 групп, но это буквы подписи,
  а объекты лежат россыпью в корне. Проверять надо долю фигур внутри групп и рендер каждой группы отдельно.
- Проба автогруппировки (порядок отрисовки + перекрытие bbox + вложение по охвату) на 3 файлах провалилась:
  человек за столом распался примерно на 25 кусков, кресло и лампа разрезаны, DVD-плеер склеился с тумбой.
  Причина принципиальная: в плоских экспортах части человека чередуются по z с мебелью (ноги за столом,
  руки перед ним). Одной группой человека не сделать, не изменив картинку.

### Этап 4 — извлечение в компонент и библиотека
- Справа при выделении — поле «Название» (пустое → «Элемент из «…»») и «Добавить в библиотеку»;
  после добавления — уведомление «Добавлено в библиотеку» на 2 с (`src/components/Toast.tsx`).
- `src/lib/extract.ts` — чистые функции над DOM, исходник только читается:
  - выделенные `<g>` (несколько через Shift) клонируются в порядке документа, а не клика;
  - трансформации предков сворачиваются в `matrix()` на клоне (свой парсер `transform`, без `getCTM`,
    чтобы работало в jsdom); предок с `clip-path`/`mask`/`filter`/`opacity` становится обёрткой `<g>`
    с накопленной трансформацией — обрезка остаётся в правильных координатах. Соседние элементы под
    одним таким предком делят одну обёртку, пока это не нарушает порядок отрисовки;
  - наследуемые атрибуты предков (`fill-rule`, `clip-rule`, `stroke-*`, `fill` и т.д. — у гоферов
    `fill-rule="evenodd"` и `stroke-linejoin` висят на корневом `<svg>`) переносятся на клон, если он
    их не задаёт; то же для скопированных defs;
  - `collectDefs` рекурсивно идёт по `url(#…)` в любых атрибутах/`style` и `href`/`xlink:href`
    (градиент → градиент, clipPath → clipPath, mask → градиент); элементы уже внутри выделения не
    дублируются; в гоферах `clipPath` лежат инлайн рядом с группами, а не в `<defs>` — тоже находятся;
  - `prefixIds` — всем id префикс `<id компонента>-`, ссылки переписываются; ссылки на чужие id не трогаются;
  - рамка = объединение рамок выделенных групп из этапа 3 (с учётом clip-path, считается в браузере
    через `getBBox`/`getCTM`) → `translate(-x -y)` на корневой `<g>`, `width`/`height`.
- Компонент `{id, name, sourceId, markup, defs, width, height, createdAt}` хранится в IndexedDB
  (`idb-keyval`, база `svg-composer`, store `library`, ключ = id) — `src/store/library.ts`.
- Вкладка «Библиотека» (`src/components/LibraryGrid.tsx`): превью — `<img>` с data-URL (id превью
  изолированы от открытого исходника), название, «из NN Название исходника», переименование
  (Enter/blur — сохранить, Esc — отмена), удаление без подтверждения.
- Тесты: `npm test` (vitest + jsdom), `src/lib/extract.test.ts` — 8 тестов: переименование id и
  ссылок, рекурсивный сбор defs, свёртка трансформаций и наследуемых атрибутов, обёртка с clip-path,
  объединение нескольких элементов (порядок, общая обёртка, рамка).
- Проверено Playwright в Chromium: по элементу из s16, s14, s02 (группы под `clip-path`) → перезагрузка →
  все 3 на месте; попиксельное сравнение компонента с исходником, где скрыто всё, кроме выбранной
  группы: расхождение 0 %, 0,11 % (сглаживание краёв), 0 %; все ссылки разрешаются, все id с префиксом.
  Переименование и удаление переживают перезагрузку. Shift+2 группы в s04 → один компонент 59,8×130,2.
- **Градиентов в наборе гоферов нет ни в одном из 20 файлов** (только `clipPath`), поэтому градиенты
  проверены только тестами на синтетических SVG.

### Этап 5 — холст
- Карточка библиотеки: превью (клик — в центр холста, перетаскивание — в точку бросания), название в
  2 строки, источник мелко «NN · Название», действия иконками карандаш/корзина в углу превью с подсказками.
- Над рабочей областью переключатель «Исходник / Композиция» (`src/store/ui.ts`, `workspaceMode`);
  вкладка «Библиотека» и добавление компонента переключают на «Композицию», клик по исходнику — на «Исходник».
  Открытый исходник и выделение в нём сохраняются при переключении.
- Холст (`src/components/CompositionCanvas.tsx`, `src/store/canvas.ts`) — чистый SVG, белый лист
  1200×800 по умолчанию, размер меняется полями «Холст Ш × В» в панели; вид = `{zoom, x, y}`, задаётся
  через `viewBox` корневого `<svg>`. Пока пользователь не трогал зум/пан, лист вписан с отступом 24px и
  следует за размером окна; «Вписать» возвращает это поведение.
- Объект `{id, componentId, name, x, y, scale, rotation, flipX}`; `x, y` — левый верхний угол
  неповёрнутой рамки, поворот вокруг центра. Рендер — `<g transform="translate rotate scale translate">`
  (`src/lib/canvas.ts`). Новый объект — масштаб 100 %, но не больше 60 % листа.
- Общий `<defs>`: `canvasParts` переносит инлайн-`clipPath` из разметки компонента в defs (с
  наследуемыми атрибутами), убирает дубли одного определения (бывает и в defs, и в разметке) и снимает
  id, на которые никто не ссылается, — несколько экземпляров одного компонента не дают повторных id;
  defs каждого компонента выводятся один раз.
- Выделение: клик (прозрачные места внутри рамки выделенного объекта тоже ловят), рамка + 4 угловые
  ручки + ручка поворота — отдельный overlay в экранных пикселях, толщина не зависит от зума.
  Масштаб угла — проекция курсора на диагональ, противоположный угол стоит на месте. Поворот — Shift
  даёт шаг 15°. Перетаскивание, ←↑→↓ — 1px, Shift — 10px, Esc / клик мимо — снять выделение.
- Зум колесом/щипком трекпада (ctrl+wheel; в Safari ещё `gesture*`) к точке курсора, 5 %…2000 %;
  пан — пробел + перетаскивание или средняя кнопка.
- Справа: «Слои» — список объектов (сверху верхний), клик выделяет; «Свойства» — X, Y, масштаб %,
  угол °, применяются при вводе, Enter/Esc уводят фокус обратно к холсту.
- Удаление компонента из библиотеки убирает его экземпляры с холста. Холст пока не сохраняется
  (этап 7) — после перезагрузки пуст.
- Тесты: `src/lib/canvas.test.ts` — геометрия (позиция, поворот, обратное преобразование с отражением,
  нормализация угла), перенос defs и снятие лишних id, дедупликация определений; всего 15 тестов.
- Проверено Playwright в Chromium и WebKit (движок Safari, сборка Playwright WebKit 26, не настоящий

### Правки после этапа 5
- Клик в исходнике сразу выбирает осмысленный объект: от кликнутой группы подъём вверх, пока группа

  `src/store/editor.ts`). Площадь сцены — общая рамка групп верхнего уровня, без пустых полей viewBox.

- Новый объект на холсте масштабируется так, что его бо́льшая сторона = 35 % высоты холста, и ставится в
  центр видимой области (с зумом/паном — в центр экрана, ограничено листом). Перетаскивание из
  библиотеки — по-прежнему в точку бросания.
- Режим «Композиция» при каждом открытии вписывает лист целиком с отступом 24px; «Вписать» — то же.
- Тесты: +2 на `meaningfulGroup` (всего 17).
- Проверено Playwright в WebKit при 1440×900: клик по телу гофера в s01 выбирает всего гофера с лицом

### Баг «капли без лица» (17.10.2026) — причина в выборе группы, не в извлечении
Жалоба: в Safari превью и холст показывают у гоферов голубое тело без глаз, рта и лап, у фонаря в s12 —
гладкий круг без полосок.
- Диагностика: выгружен компонент s13, группа №9, в WebKit. Все 11 потомков клонированы, все
  `url(#…)` разрешаются, трансформации верные. Попиксельно компонент совпадает с исходником, где
  оставлена только эта группа (WebKit и Chromium).
- Причина: **группа №9 — это и есть только тело** (заливка, тени, контур). Глаза, рот и лапы — соседняя
  группа №17, живот — №14, весь гофер — №1 (60 эл.). Рамка тела (337×508) почти совпадает с рамкой
  гофера (367×563), поэтому выделение выглядело как «весь гофер». Клик останавливался на теле по
  правилу «≥10 % площади», а тело и так больше 10 %. В s12 то же (тело №10, гофер №1).
- Фонарь s12 №40 — группа из одного красного круга; полоски — отдельные группы верхнего уровня
  (№41, №42, №61…), в исходнике с кругом не сгруппированы (как календарь в s04). **Не исправлено**:

### Этап 7 — экспорт и проекты
- В шапке (`src/components/FileMenu.tsx`): «Открыть проект», «Сохранить проект», «Скачать PNG», «Скачать SVG».
  ⌘E / Ctrl+E — скачать SVG из любого режима. Кнопки экспорта неактивны, если видимых объектов нет.
- Экспорт SVG — чистая функция `exportSvg` (`src/lib/exportSvg.ts`), строится через DOMParser (работает и в
  jsdom): `viewBox`, `width`, `height` = размер холста; `<rect id="background" fill="#fff">`; один `<defs>`;
  каждый видимый объект снизу вверх — `<g id="имя-объекта" data-source="sXX" transform="…">` с разметкой
  компонента внутри. Никаких рамок, ручек, классов и `data-object-id`.
  - id объекта — из названия: строчные буквы/цифры, остальное → `-` («Гофер справа» → `гофер-справа`;
    кириллица в id допустима в XML); повтор → `-2`, `-3`; начинается не с буквы → `object-…`.
  - defs: определения каждого использованного компонента один раз (`canvasParts`, как на холсте), повтор id
    отбрасывается, затем остаётся только то, до чего можно дойти по ссылкам от нарисованного
    (градиент → градиент, clipPath → …). Скрытые объекты и объекты без компонента не экспортируются,
    их defs тоже.
  - Если в разметке компонента остались id (на них ссылается сама разметка, например `<use>`), у второго и
    следующих экземпляров они получают префикс id объекта.
  - Файл `composition-YYYY-MM-DD.svg` (локальная дата), с `<?xml …?>`.
- PNG: растр из того же SVG-файла (`<img>` → `<canvas>` 2× → `toBlob`), `composition-YYYY-MM-DD.png`;
  масштаб уменьшается, если картинка больше 16 Мпикс (предел Safari). Работает в Chromium и WebKit (e2e).
- Проект (`src/lib/project.ts`): JSON `{format: "svg-composer-project", version: 1, savedAt, canvas,
  objects, components}` — внутри только компоненты, которые использует холст (включая скрытые объекты),
  целиком с разметкой и defs. Файл `project-YYYY-MM-DD.json`.
  - Открытие: `parseProject` проверяет JSON, формат, версию, поля холста/объектов/компонентов с типами,
    что у каждого объекта есть компонент в файле, уникальность id объектов; разметка компонентов должна
    разбираться как SVG и не содержать `script`/`foreignObject`/`on*`/`javascript:`. Лишние поля
    отбрасываются. Ошибка — красная плашка под кнопками: «Не удалось открыть «файл». <причина>», холст не
    меняется.
  - Компоненты, которых нет в библиотеке, добавляются (`addMissing`; уже имеющиеся с тем же id, возможно
    переименованные, не трогаются). Холст заменяется одним шагом истории (`replace`) — ⌘Z возвращает

### Логические объекты: гофер целиком во всех 20 файлах (17.10.2026)
Жалоба: в s08 клик по гоферу давал группу №9 — розовое тело без глаз и рта (лицо — соседняя группа №17);
в s18 — голубую каплю №23 размером 1606,6×2423,4.
- **Размер в s18 считался верно.** У s18 и s19 viewBox 5000×5000 (у остальных 144 или 600). Рамка №23,
  проверенная рендером группы отдельно в WebKit, — 2625…4238 × 2369…4794 против индекса 2626…4233 ×
  2369…4792 (расхождение ≤ 6 единиц из 5000). Гофер занимает 33×49 % иллюстрации. Чтобы числа не путали,
  панель «Выделение» теперь показывает размер и в процентах: «1647,7 × 2465,2 (33 × 49 % иллюстрации)».
  Тест для всех 20 файлов: размер выбранного объекта не больше иллюстрации.
- **Причина «голых тел»:** гоферы нарисованы соседними группами — уши/лапы, тело (заливка, тень,
  контур), живот, точки, лицо поверх. Общей группы у персонажа нет, правило «родитель ≤ 1,5× — слой»
  из прошлого исправления срабатывало только там, где она есть (s12, s13).
- **Решение — логические объекты** (`src/lib/objects.ts`, считаются при индексации исходника,
  `owners` в `src/store/editor.ts`), не в `prepare-svg`: нужны рамки с учётом `clip-path`, а они есть
  только в браузере. Каждая группа прикрепляется к самому тесному соседу (тот же родитель), внутри
  рамки которого лежит ≥ 85 % её рамки; цепочки дают объект: глаза → лицо → тело.
  Ограничения — **отступления от буквы задачи, найденные на реальных файлах**, без них правило 85 %
  ломало другие картинки:
  - одиночная фигура (лист календаря, круг фонаря, удочка) принимает только простые части (≤ 2 эл.):
    полоски фонаря — да, гофер перед календарём (s04) — нет;
  - составная часть, нарисованная *под* контейнером, должна быть в 8+ раз меньше: иначе левый гофер в
    s20 становился частью группы «гирлянда + ёлка + правый гофер», нарисованной поверх него;
  - часть и контейнер нарисованы подряд: между ними допустимы только другие части того же объекта,
    мелкая деталь, лежащая на контейнере (лапа в s10), или что-то крупнее контейнера (удочка поверх
    гофера в s14 — её рамка 526×384 накрывает гофера, и без этого правила она «съедала» лицо).
- Клик: подъём по уровням теперь сравнивает с родителем рамку всего объекта, а не одной группы (s10:
  тело+живот+лицо почти равны группе гофера → берётся она). Клик выделяет все группы объекта, рамка
  одна на объект; наведение показывает её же. ↓ — к кликнутой группе, дальше к её частям; ↑ — снова
  объект, потом родитель. Shift+клик внутри выделенного объекта снимает его целиком. Выделение рамкой
  не режет объект по тем же рамкам объектов. В панели «Выделение» объект — одна карточка.
