# SVG Composer

Сервис собирает композиции для иллюстраций в разных форматах из готовых объектов библиотеки (10 объектов,
экспорт из Figma). Объекты **не генерируются и не меняются**: только расположение, размер, главный/фоновый
вид и цвета в рамках схемы. Результат — чистый векторный SVG с отдельными слоями, который открывается в
Figma, Illustrator и браузере.

**Демо:** https://svg-composer.vercel.app · **Репозиторий:** https://github.com/fedorov17808-svg/svg-composer

Откройте демо: сразу видна собранная композиция «Финансовая грамотность». Ещё 9 готовых — в меню
**Проект → Открыть пример** (3 метафоры × 3 формата, в разных схемах; файлы в `public/examples/`).

Стек: Vite 8, React 19, TypeScript 6, Zustand 5, IndexedDB (`idb-keyval`), Vitest, Playwright. Сервера нет,
всё работает в браузере; единственная серверная часть — необязательная функция `api/metaphor.ts` для Claude.

## Как пользоваться

**Сценарий 1 — метафора.** Режим «Метафора», вводите заголовок («Удалённая работа») и «Собрать»: сервис
подбирает 2–4 объекта по смыслу, показывает, почему именно они («монета — финансы»), и компонует.
**Сценарий 2 — объекты.** Режим «Объекты», названия через запятую («наушники, лампа, книга»; синонимы и
опечатки понимаются). В обоих случаях объекты потом правятся чипами (× убрать, «+ объект» добавить), а
«Другой вариант» даёт другую раскладку тех же объектов.

Дальше: формат (1:1, 2:1, 2:3 или свой размер), размер **L/S** для всей композиции, цветовая схема
(сиреневая, персиковая, мятная или своя палитра), у выделенного объекта — «Главный / Фоновый» и вариант
цвета. Объекты двигаются, масштабируются, поворачиваются, дублируются; ⌘Z отменяет. **Экспорт → SVG** (⌘E)
или PNG. Все клавиши и подсказки — в справке (кнопка **?**). Справка и сам интерфейс рассчитаны на окно
от 1024 px; в более узком боковые панели сворачиваются в рейки и ничего не перекрывают.

## Запуск локально

```bash
npm install
npm run dev        # http://localhost:5173
```

| Скрипт | Что делает |
| --- | --- |
| `npm run dev` / `build` / `preview` | Dev-сервер; проверка типов и сборка в `dist/`; просмотр сборки |
| `npm run import-library` | Разбирает `figma-library/Размер {L,S}.svg` → `public/library/` (см. «Архитектура») и проверяет результат |
| `npm run examples` | Собирает 9 примеров в `public/examples/` кодом самого приложения и контактный лист `scripts/out/examples/sheet.png` |
| `npm run auto-layout-sheet`, `metaphors-sheet` | Контактные листы автокомпоновки и подбора по метафоре для проверки глазами |
| `npm test` | Модульные тесты (Vitest) |
| `npm run test:e2e` | Браузерные тесты (Playwright, Chromium и WebKit); один раз: `npx playwright install chromium webkit` |
| `npm run lint` | oxlint |

### Режим Claude API (выключен, готов)

Подбор по метафоре работает без внешних сервисов. Для разбора метафор моделью есть серверная функция
`api/metaphor.ts` (Claude через `@anthropic-ai/sdk`, ответ — JSON с `id` только из библиотеки, затем
проверяется ещё раз на странице). **Включается одним ключом:** `ANTHROPIC_API_KEY` в переменных окружения
Vercel (или в `.env` для `npm run dev`) и редеплой. Страница при загрузке спрашивает `GET /api/metaphor`, есть
ли ключ; нет — подбор локальный и мгновенный, есть — запрос с ожиданием до 8 с и тихим откатом на локальный
при любой ошибке. Ключ остаётся на сервере и в браузер не попадает. Сейчас ключа нет, на реальном ключе
режим не проверялся (только на поддельном клиенте и подменённом ответе сервера).

## Архитектура

```
figma-library/*.svg ──import-library──▶ public/library/{L,S}/{main,bg}/*.svg + manifest.json + palettes.json
                                                       │
   метафора ──pickLocal / Claude──▶ объекты ──autoLayout──▶ Холст (SVG) ──recolor по схеме──▶ экспорт SVG / PNG
   названия ──parseNames──────────┘                          IndexedDB: свои палитры, автосохранение
```

- **Импорт библиотеки** (`scripts/import-library.mjs`). Экспорт из Figma — это ~1500 плоских `path` без групп и
  id, подписи превращены в контуры, а фигуры разных объектов перемешаны. Объекты находятся **по геометрии**
  в настоящем браузере (нужны рамки): две подписи-раздела («Главные», «Фоновые») делят лист; внутри раздела
  фигуры с пересекающимися рамками объединяются в кластеры, 10 крупнейших — объекты, мелкие присоединяются к
  ближайшему. **Нормализация:** каждый объект переносится в начало координат одной `<g transform>`, пути
  копируются как есть (порядок рисования сохранён), у viewBox точные размеры; любые id получают префикс файла, а
  ссылки `url(#…)`/`href` переписываются. Скрипт падает, если объектов не 10 в рядах 4+4+2, у главной и фоновой
  версий разные размеры, рамка файла не совпадает с нарисованными пикселями или есть цвет вне схемы. Каждый из 40
  файлов (10 объектов × главный/фоновый × L/S) просмотрен глазами.
- **Хранение.** `manifest.json` (id, русское название, синонимы, теги смысла, файлы и размеры версий) и
  `palettes.json` (3 схемы × 4 цвета фона + 4 цвета объектов, считаны с образцов на листе) лежат в
  `public/library/`; свои палитры пользователя — в IndexedDB; композиция автосохраняется в отдельную базу и
  открывается после перезагрузки; проект — JSON (с проверкой формата), в нём палитра, формат, размер, `auto`.
- **Перекраска по слотам** (`src/lib/palette.ts`). Все объекты нарисованы в сиреневой схеме, и каждый её цвет
  — слот: фон №1–4 и объект №1–4. Другая схема (в том числе загруженная JSON из 8 цветов) заменяет цвет по
  слоту. Слоты фона переходят только в слоты фона, поэтому цвета объектов не попадают ни в фон, ни в фоновые
  объекты (цвета фона в объектах — можно); проверено перекраской всех 40 файлов во все схемы.
- **Главный / фоновый, L/S.** Главный — цветной, фоновый — монохром из двух цветов фона; переключение
  подменяет файл версии на месте. Размер L/S меняет файлы всей композиции, раскладка остаётся (у L и S одни
  пропорции); масштаб объекта — только пропорциональный, поэтому объекты не искажаются.
- **Автокомпоновка** (`src/lib/autoLayout.ts`, чистая функция от `seed`: один seed — одна раскладка).
  *Главные* (первые три): размеры — пропорции листа в степени 0,35, чтобы монета рядом с папкой не терялась;
  направление зависит от формата (широкий — ряд с наклоном, вертикальный — столбец, квадрат — диагональ);
  каждый следующий ставится на минимальный шаг, при котором перекрытие ≤ 1–6 % меньшего; группа
  масштабируется до максимума внутри поля; 48 попыток на вариант, оценка по заполнению кадра, из трёх лучших
  берётся один по seed. *Фоновые*: сначала лишние объекты списка, затем «немного» (до 2) / «много» (до 4) из
  тех же тем, что главные; они крупнее главных, стоят на краях и в углах, частично уходя за кадр, там, где
  закрывают больше всего пустого. Слои: фоновые, затем главные от дальнего к ближнему, как в изометрии.
- **Подбор по метафоре** (`src/lib/metaphor.ts`). *Локально:* нормализация и простой стемминг, вес совпадения —
  фраза из таблицы 28 частых метафор (3) > название или синоним (1,5) > тег смысла (1); берутся 2–4 объекта,
  одиночному добавляется парный; причина — слово самого объекта. *Claude (необязательно):* см. выше.
- **Сохранено из v1:** холст на чистом SVG (зум, панорама, ручки, слои, блокировка), история undo/redo, экспорт SVG
  (`src/lib/exportSvg.ts`: `viewBox` по холсту, объекты отдельными `<g id>`, один `<defs>`, без служебных
  атрибутов) и PNG 2× из того же SVG, проекты, автосохранение, тесты, деплой.

## Тесты

- **Vitest, 179 тестов:** импорт и цвета всех 40 файлов, перекраска и слоты, форматы и L/S, парсер названий,
  автокомпоновка (8 наборов × 3 формата × 3 количества фона × 4 seed: главные в кадре, перекрытие, пропорции,
  детерминизм), подбор по метафоре (15 метафор, откат с Claude), функция `api/metaphor`, история, холст, экспорт, проекты.
- **Playwright, Chromium + WebKit:** библиотека, холст, палитры, форматы, оба сценария, экспорт и проекты,
  первый запуск с демо, мгновенный локальный подбор при медленном сервере, отсутствие наложения панелей от
  800 до 1440 px, меню примеров, справка.

## Известные ограничения

- Версии S в макете местами отличаются от L не только детализацией (у главного телефона S на экране нет пазла,
  у главной монеты S — замка); используются как есть.
- Локальный подбор по метафоре знает ограниченный словарь (теги и 28 фраз); незнакомая тема — «ничего не нашлось»
  и ручной выбор объектов. Claude это закрывает, но без ключа не проверен.
- Автокомпоновка — эвристика: даёт аккуратный результат, но не заменяет дизайнера; всегда есть «Другой вариант» и ручная правка.
- Свои палитры хранятся в браузере (IndexedDB) и не синхронизируются между устройствами; в проект они попадают.
- Автотесты идут в WebKit из Playwright, а не в Safari.app; Safari.app проверялся только вручную.

**Что дальше:** плагин Figma (забирать объекты и схемы прямо из макета, без ручного экспорта и импорта);
новые схемы и объекты через тот же `import-library`; режим Claude на реальном ключе с проверкой качества
подбора; тема/сюжет композиции (подсказки по расположению объектов относительно друг друга); сохранение
композиции обратно в Figma.

## AI-инструменты

Проект сделан с **Claude Code**.
- **Планирование по этапам:** `PLAN.md` и `TASK-v2.md` — этапы с критериями готовности; `PROGRESS.md` —
  журнал каждого этапа: что сделано, как проверено, что не получилось.

- **Проверка глазами:** контактные листы (`scripts/out/…`) для импортированных объектов, автокомпоновки,
  подбора по метафоре и примеров; по ним правились алгоритмы (размеры главных, зазоры, перекрытия).
- **Тесты:** агент писал Vitest и Playwright, включая регрессии на найденные баги.
- **В продукте** AI используется только по назначению задания — для анализа метафор (режим Claude API); объекты
  он не создаёт и не меняет.
- Решения о наборе, форматах, правилах цветов и публикации принимал человек.
