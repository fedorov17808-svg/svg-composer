# SVG Composer

Веб-приложение для сборки новых иллюстраций из частей готовых SVG. Открываешь исходник, кликом или
рамкой выделяешь объект (персонажа, предмет, деталь), сохраняешь его в библиотеку как отдельный
компонент и собираешь из компонентов разных исходников новую сцену. Результат — чистый SVG, который
открывается в Figma, Illustrator и браузере с отдельными слоями.

**Демо:** _ссылка появится после деплоя_

Стек: Vite 8, React 19, TypeScript 6, Zustand 5, IndexedDB (`idb-keyval`), SVGO 4, Vitest, Playwright.
Сервера нет — всё работает в браузере.

## Запуск локально

```bash
npm install
npm run dev        # http://localhost:5173
```

| Скрипт | Что делает |
| --- | --- |
| `npm run dev` | Dev-сервер Vite |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run prepare-svg` | Нормализует `raw-svg/*.svg` → `public/sources/s01…s20.svg` + `manifest.json` |
| `npm run seed` | Собирает демо-библиотеку (`public/seed-library.json`) и примеры (`public/examples/`) кодом самого приложения в Chromium |
| `npm test` | Модульные тесты (Vitest + jsdom) |
| `npm run test:e2e` | E2E-тесты (Playwright, Chromium и WebKit). Перед первым запуском: `npx playwright install chromium webkit` |
| `npm run lint` | oxlint |

## Демо-сценарий за 2 минуты

1. Слева вкладка **«Исходники»** — кликни по любой карточке, например «Гофер у пагоды» (s11).
2. Кликни по гоферу — выделится весь персонаж. **↑/↓** — уровень выше/ниже (например, только голова).
   Чтобы взять несвязанные детали, протяни **рамку** с пустого места; **Shift** — добавить к выделению.
3. Справа задай название и нажми **«Добавить в библиотеку»** — компонент появится на вкладке «Библиотека».
4. Повтори для двух других исходников (например, фонарь из s12 и карп из s14). Библиотека уже содержит
   12 демо-компонентов, так что этот шаг можно пропустить.
5. Перейди на холст и **перетащи** компоненты из библиотеки. Перемещай, масштабируй за углы, вращай,
   меняй порядок в панели «Слои»; ⌘Z / ⇧⌘Z — отмена и повтор.
6. **Экспорт ▾ → SVG** (⌘E). Готовые сцены — в «Проект ▾ → Примеры».
7. Перетащи скачанный файл в Figma — каждый объект будет отдельной группой с названием.

Клавиши — в справке (кнопка **?** в шапке).

## Архитектура

```
raw-svg/ ──prepare-svg──▶ public/sources/ ──▶ Исходник ──выделение──▶ extract ──▶ Библиотека (IndexedDB)
                                                                                     │
                                                         экспорт SVG / PNG ◀── Холст ◀┘
```

- **Нормализация исходников** (`scripts/prepare-svg.mjs`): SVGO preset-default без схлопывания групп и
  слияния путей (структура `<g>` сохраняется); `inlineStyles` + `convertStyleToAttrs` — CSS-классы
  превращаются в атрибуты; `prefixIds` — у каждого файла свои id (`s01_…`) с переписанными `url(#…)`/`href`.
  Встроенная проверка падает, если групп мало, остались `style`/`class` или есть растровые `<image>`.
- **Выделение** (`src/lib/svgGroups.ts`, `objects.ts`, `selection.ts`): индекс групп и фигур с рамками
  в единицах viewBox (с учётом всех трансформаций и `clip-path`). Клик выбирает «логический объект» —
  поднимается от фигуры до персонажа или предмета целиком (слой, почти равный родителю, считается частью
  объекта; маленькие лапы, касающиеся персонажа, прицепляются; две фигуры персонажей не склеиваются).
  ↑/↓ — уровни группы. Рамка выбирает детали, не разрезая объекты меньше себя. Исходник только читается.
- **Извлечение** (`src/lib/extract.ts`, чистые функции над DOM): клонирование в порядке документа;
  сбор нужных `defs` рекурсивно по `url(#…)` и `href` (`clipPath`, градиенты, маски); переименование
  всех id с префиксом компонента; трансформации предков сворачиваются в `matrix()`, а предки с
  `clip-path`/`mask`/`opacity` становятся обёртками; наследуемые атрибуты (`fill-rule`, `stroke-*`)
  переносятся; координаты нормализуются — компонент начинается в (0, 0) со своими `width`/`height`.
- **Хранение**: компоненты — IndexedDB (`idb-keyval`); текущая композиция автосохраняется в отдельную базу.
  При первом запуске библиотека заполняется из `public/seed-library.json`. Проект сохраняется/открывается
  как JSON со всеми используемыми компонентами (с проверкой формата и запретом `script`/`on*`).
- **Холст** (`CompositionCanvas.tsx`, `src/store/canvas.ts`): чистый SVG без canvas-библиотек — объекты
  как `<g transform>`, ручки поверх; зум и панорама; дублирование, отражение, порядок слоёв, блокировка, скрытие;
  история undo/redo снимками состояния (`src/lib/history.ts`).
- **Экспорт** (`src/lib/exportSvg.ts`): чистый SVG — `viewBox` по холсту, белый фон, один общий `<defs>`
  только с достижимыми определениями, каждый объект — отдельный `<g id="имя" data-source="s12"
  transform="…">`; без служебных атрибутов, ручек и классов. PNG 2× растеризуется из того же SVG.

## Почему гоферы

Нужны иллюстрации, где объекты действительно сгруппированы: иначе «выделить персонажа» нечего.
Проверялись Flowbite Illustrations, GLPI, GitLab SVGs, Open Doodles, Illlustrations, Lukasz Adam,
Momentum, Wix, Humaaans — большинство экспортированы из Figma/Sketch плоско: фигуры лежат россыпью в
корне, а большое число `<g>` часто означает буквы подписи. Попытка автогруппировки плоских файлов
провалилась (части человека чередуются по z с мебелью). **Free Gophers Pack** экспортирован из Affinity
Designer с настоящими вложенными группами (14–124 группы, глубина 5–10), в едином стиле, с персонажами и
предметами, под CC0.

## Известные ограничения

- **Йети в s18** нарисован вперемешку с гофером — ни клик, ни рамка не берут его отдельно; собирается
  Shift+кликами (тело, рога, лицо, глаза).
- **s02:** клик по верёвке или забору даёт всю группу забора с левым гофером.
- **Фонарь s12:** полоски — отдельные группы верхнего уровня; кисточки состоят из линий нулевой ширины,
  у их групп пустая рамка — рамкой не взять, Shift+клик раздувает размер компонента. В демо фонарь без кисточек.
- **s04:** календарь — ~50 несгруппированных фигур, берётся рамкой.
- В наборе нет градиентов — их поддержка проверена только тестами на синтетических SVG.
- Автотесты идут в WebKit из Playwright, а не в Safari.app; Safari.app проверялся только вручную.
- Старые компоненты в IndexedDB не обновляются при изменении алгоритма выделения — их надо извлечь заново.

**Что улучшил бы дальше:** рамки для линий нулевой ширины в `collectGroups`; ручная группировка деталей в
исходнике; отражение и цвет у объектов на холсте; экспорт выбранных объектов; загрузка своих SVG через
тот же конвейер нормализации; синхронизация библиотеки между устройствами.

## Тесты

- **Vitest (94 теста, `src/**/*.test.ts`):** извлечение (переименование id и ссылок, рекурсивные defs,
  свёртка трансформаций, `clip-path`-обёртки, дубли `clipPath`), логические объекты и рамка, история
  undo/redo, слои, операции холста, экспорт SVG (структура, defs, уникальные id), формат проекта и его
  проверка, имена по умолчанию.
- **Playwright (64 теста, `e2e/`, Chromium + WebKit):** попиксельное сравнение извлечённого компонента
  с исходником, выбор объекта кликом во всех 20 исходниках, выделение рамкой реальной мышью,
  редактирование холста и клавиши, экспорт SVG/PNG и проекты, шапка, справка, демо и примеры при 1024
  и 1440px.

## AI-инструменты

Проект сделан с **Claude Code** (модель Claude Opus).
- **Планирование по этапам:** `PLAN.md` — 9 этапов с критериями готовности; `PROGRESS.md` — журнал
  каждого этапа: что сделано, как проверено, что не получилось.
- **Генерация кода:** весь код писался агентом по этапам, после каждого — build, lint, тесты, коммит.
- **Тесты:** агент писал Vitest и Playwright-тесты (WebKit как движок Safari, Chromium), включая
  попиксельные сравнения рендера и тесты-регрессии на найденные баги.
- **Вручную** в Safari проверялись выделение кликом, вид извлечённых компонентов и холста; по жалобам из
  ручной проверки найдены и исправлены, например, «гоферы без лица» (клик выбирал слой тела, а не
  персонажа). Решения о наборе иллюстраций и о границах автогруппировки принимались человеком.
